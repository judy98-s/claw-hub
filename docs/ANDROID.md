# 안드로이드 앱 (Play 스토어)

사장님 대시보드를 **TWA**(Trusted Web Activity)로 감싸 Play 스토어에 올린다.
지금 있는 웹을 그대로 띄우는 껍데기라 **코드베이스가 늘지 않는다.** 웹을 고치면
앱도 같이 고쳐지고, 앱을 다시 올릴 필요도 없다.

> **손님용 앱은 만들지 않는다.** 고장난 기계 앞에서 앱을 설치할 사람은 없다.
> QR → 모바일 웹이 정답이고 지금 그렇게 되어 있다.

---

## 먼저 정할 것

| 항목 | 예 | 비고 |
|---|---|---|
| 도메인 | `claw.example.com` | HTTPS 필수. TWA 는 http 로는 동작하지 않는다 |
| 패키지 이름 | `com.example.clawhub` | **한 번 정하면 못 바꾼다.** 도메인을 거꾸로 쓰는 게 관례 |
| 앱 이름 | claw-hub 접수함 | 스토어에 보이는 이름 |

패키지 이름은 스토어에서 앱의 주민번호다. 오타가 있어도 나중에 못 고치고,
새 앱으로 다시 올려야 한다.

## 1. 준비

```bash
npm install -g @bubblewrap/cli
```

Bubblewrap 이 JDK 와 안드로이드 SDK 를 알아서 받는다(첫 실행에 몇 분).

## 2. 서명 키 만들기

```bash
keytool -genkeypair -v \
  -keystore android.keystore \
  -alias clawhub \
  -keyalg RSA -keysize 2048 -validity 10000
```

> **이 파일과 비밀번호를 잃어버리면 같은 앱을 영원히 업데이트할 수 없다.**
> 비밀번호 관리자에 넣고, 저장소에는 절대 올리지 않는다(`.gitignore` 에 이미 있다).

## 3. 지문 확인

```bash
keytool -list -v -keystore android.keystore -alias clawhub | grep SHA256
```

`AB:CD:...` 형태의 64자리 값이 나온다.

## 4. 서버에 지문 등록

`.env` 에 넣고 웹을 재시작한다.

```
ANDROID_PACKAGE_NAME=com.example.clawhub
ANDROID_SHA256_FINGERPRINTS=AB:CD:...:EF
```

확인:

```bash
curl https://claw.example.com/.well-known/assetlinks.json
```

패키지 이름과 지문이 보이면 된다. **빈 배열 `[]` 이면 환경변수가 안 들어간 것이다.**

> 이게 맞지 않으면 앱 안에 **브라우저 주소창이 남는다.** 앱이 아니라 크롬 창처럼
> 보이고, 심사에서 지적받는다.

## 5. 빌드

`web/twa-manifest.json` 의 `host`, `packageId`, `iconUrl` 들을 실제 도메인으로 바꾼 뒤:

```bash
cd web
npx @bubblewrap/cli init --manifest https://claw.example.com/manifest.webmanifest
npx @bubblewrap/cli build
```

`app-release-bundle.aab` 가 나온다. 이게 스토어에 올릴 파일이다.

## 6. Play 앱 서명 지문 추가 (중요)

Play 콘솔에 올리면 구글이 **자신의 키로 다시 서명**한다. 그래서 스토어에서 받은
앱의 지문은 내 keystore 지문과 다르다.

콘솔 → **설정 → 앱 서명** 에서 `앱 서명 키 인증서`의 SHA-256 지문을 복사해
`.env` 에 **쉼표로 이어서** 넣는다.

```
ANDROID_SHA256_FINGERPRINTS=내지문,구글지문
```

이걸 빼먹으면 **내가 빌드한 apk 는 멀쩡한데 스토어에서 받은 앱만 주소창이 뜬다.**
원인을 찾기 어려운 대표적인 함정이다.

## Play 스토어 등록 절차

### 1. 콘솔 계정 ($25, 1회)

[play.google.com/console](https://play.google.com/console) 에서 개발자 등록.
개인 계정은 본인 인증(신분증)이 필요하고 며칠 걸릴 수 있다.

### 2. 등록 정보

| 항목 | 준비물 |
|---|---|
| 앱 아이콘 | `web/public/icons/play-store-512.png` (512×512) |
| 스크린샷 | 폰 크기 2장 이상 (접수함 / 신고 상세 화면) |
| 그래픽 이미지 | 1024×500 |
| 짧은 설명 | 80자 이내 |
| 자세한 설명 | 4000자 이내 |
| 개인정보처리방침 URL | `https://claw.example.com/privacy` |

> **개인정보처리방침의 대괄호 `[ ]` 를 반드시 채우고 올릴 것.**
> 매장명·담당자·연락처·보관 기간이 비어 있으면 심사에서 반려된다.

### 3. 데이터 보안 양식

콘솔이 "어떤 데이터를 수집하는지" 를 묻는다. 이 앱은 다음을 수집한다고 답해야 한다.

- **개인 정보**: 이름(예금주), 전화번호
- **금융 정보**: 기타 금융 정보 (계좌번호)
- **사진**: 사용자가 첨부한 사진
- 전송 중 암호화: 예 / 삭제 요청 가능: 예

사실과 다르게 적으면 앱이 내려간다. 위 목록은 실제 동작과 맞춰 적은 것이다.

### 4. 비공개 테스트 (개인 계정 필수)

개인 개발자 계정은 **12명 이상이 14일 연속** 테스트에 참여해야 프로덕션 출시를
신청할 수 있다. 테스터는 구글 계정 이메일로 초대한다.

**여기가 가장 오래 걸린다.** 가족·지인 12명을 미리 모아두는 편이 낫다.
14일은 "설치해두기만" 해도 되지만, 중간에 인원이 12명 아래로 떨어지면 다시 센다.

회사(법인) 계정은 이 요건이 없다.

### 5. 심사

보통 1~3일. 반려되면 사유가 콘솔에 뜬다. 이 앱에서 자주 걸리는 것:

- 개인정보처리방침 URL 이 안 열리거나 대괄호가 남아 있음
- 데이터 보안 양식과 실제 동작이 다름
- assetlinks 미설정으로 주소창이 보임 → "웹사이트를 그대로 감싼 앱"으로 판단

## 업데이트할 때

웹만 고쳤으면 **아무것도 안 해도 된다.** 앱은 웹을 띄우는 껍데기라 서버에
배포하는 순간 반영된다.

앱 이름·아이콘·패키지 설정을 바꿀 때만 다시 빌드해 올린다. 그때는
`twa-manifest.json` 의 `appVersionCode` 를 1 올려야 한다(같은 번호는 거부된다).

## iOS 는?

애플은 TWA 같은 방식을 허용하지 않는다. "웹사이트를 감싸기만 한 앱"은 심사에서
거부된다(가이드라인 4.2). iOS 를 하려면 네이티브 앱을 따로 만들어야 하고,
연 $99 가 든다.

**당분간은 사파리에서 "홈 화면에 추가"로 충분하다.** 아이콘이 생기고 주소창 없이
뜬다. 푸시 알림도 iOS 16.4 부터 홈 화면에 추가한 경우 동작한다.
